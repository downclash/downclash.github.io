V2Ray 配置格式详解：分享链接、Base64 订阅、JSON 与 Clash YAML

V2Ray 配置格式包括单节点分享链接、Base64 订阅及核心 JSON，Clash YAML 还可能带规则与策略组。对照用途和接收端选择导入入口，了解哪些内容可迁移、哪些字段需要重新配置。

V2Ray 订阅、分享链接和 JSON 有什么区别？

V2Ray 订阅地址负责获取和更新配置，vless:// 等分享链接通常描述单个节点；Base64 可能只是节点列表的编码。Xray、V2Fly、sing-box 的 JSON 与 Clash / Mihomo YAML 各有字段规范。导入前先确认接收端支持什么，修改后缀不会完成格式转换。

配置能否导入，取决于数据表达的对象和接收端的解析能力。一个节点支持 VLESS，不等于所有 VLESS 配置都能互相读取；两份文件都是 JSON，也不代表字段含义相同。本教程帮助判断手里的内容应交给哪个入口，不提供在线转换服务。

V2Ray 配置格式对照：URL、URI、Base64 与完整配置

形式通常表达什么常见接收入口
HTTP(S) URL远端资源地址，可能用于订阅更新订阅管理；必须确认响应格式
vmess://、vless://、trojan:// 等节点连接参数分享链接、剪贴板或二维码导入
多行 URI / Base64 内容一组节点，具体封装由实现决定兼容的节点列表或订阅解析器
Xray / V2Fly / sing-box JSON对应核心的入站、出站、路由等结构该核心或客户端支持的自定义配置入口
Clash / Mihomo YAML节点、策略组、规则与其他配置兼容的完整配置或节点提取入口

URL 是获取数据的方式，不是配置格式名称；同一个订阅 URL 也可能根据服务端设置返回不同内容。识别时应同时看来源说明、响应内容和接收端文档。

节点分享链接携带哪些参数？

VLESS 和 Trojan 等分享链接通常把认证、地址和端口放在 URI 中，将传输、安全参数等放在查询部分，备注放在片段中。VMess 的常见分享形式则把一份节点 JSON 编码在 vmess:// 后面。不同提案与版本支持的字段仍需逐项核对。

下面只是用于识别结构的示意，包含占位值，不能建立连接。导入真实节点时应使用提供方给出的完整内容，而不是根据这段示例猜参数。

vless://UUID占位@server.example.com:443?type=tcp&security=tls&sni=server.example.com#节点备注

复制时不要截掉 ? 后的参数，也不要用聊天软件自动换行后的残缺片段。分享链接能够恢复节点，并不必然包含你在客户端另设的分流、DNS、分应用名单或系统代理配置。

Base64 是编码，不是加密或兼容性保证

有些订阅把多行节点 URI 包装为 Base64；VMess 分享链接内部也常使用这种编码。二者发生在不同层次，不能看到一段字母数字就判断它一定是某种节点。v2rayN 的订阅处理源码包含 Base64 处理逻辑，但这不代表任意编码内容都会变成可识别配置。

Base64 可以在本地还原，不能用来隐藏密码、UUID 或账户标识。把编码结果发给在线解析器，仍相当于交出了里面的数据。学习识别格式时使用虚构示例；真实订阅应直接交给可信客户端处理。

Xray JSON、sing-box JSON 与客户端内部格式怎么区分？

Xray、V2Fly 和 sing-box 有各自的配置规范。比如Xray 配置规范使用 routing 描述路由，sing-box 配置规范则有自己的 route 结构；出站类型和字段的位置也存在差异。把 Xray JSON 交给 sing-box，不能仅靠改后缀完成迁移。

客户端的节点记录还可能是另一种模型。v2rayN 官方说明中的 v2rayn:// 内部分享格式，用于承载客户端记录和部分标准分享链接之外的信息。它与核心直接运行的 JSON 不同，内部结构变化还可能受客户端版本影响。完整备份应使用该软件支持的方式，不能把内部格式视为所有代理工具通用标准。

导入 Clash YAML 时，哪些内容需要重新验证？

Clash / Mihomo 配置可能包含 proxies、策略组、规则、Providers、DNS 与 TUN 设置。某个客户端支持从 YAML 导入节点，并不意味着它会同步实现所有策略组、规则集或脚本。要判断“导入成功”，应说明成功的是节点提取还是整份配置运行。

  1. 先阅读当前客户端对该格式的支持说明，确认它将数据交给哪个内核。
  2. 导入后比较节点数量及关键连接字段，尤其是传输路径、TLS 服务器名称和 REALITY 参数。
  3. 分别核对当前活动节点、默认出站、直连域名与 DNS；不要以节点同名推断规则完全相同。
  4. 原配置包含不支持的策略或资源时，重新在接收端建立对应规则，或继续使用原本兼容的客户端。

V2Ray 配置无法导入时，按错误选择处理方式

错误表现可能原因可验证的处理
把 URL 导入后无节点响应是网页或不匹配格式获取当前客户端专用订阅
JSON 能解析但核心不启动语法正确，字段属于另一核心或版本查实际核心规范与首个报错字段
节点能连，分流行为不同只导入了节点，没有迁移规则对照日志分别验证代理与直连目标
节点备注相同，参数却缺失格式转换或旧解析器丢字段逐项核对原数据并查看版本修复记录

转换、迁移与恢复的最小范围

需要转换时，优先向配置提供方索取匹配格式；自行处理则保留原始数据，在本地生成独立副本，只迁移已理解的字段。先验证一个节点，再扩展规则和 DNS，避免把整份旧配置直接覆盖客户端生成文件。停止测试后恢复原活动配置和代理设置。

第三方转换服务会接触订阅内容，不能因为网址使用 HTTPS 就推定它不会记录数据。若链接已经泄露，应处理提供方的令牌更新或权限撤销，而不是再套一层 Base64。

V2Ray 配置格式常见问题

把 Clash 的 YAML 改名为 JSON，就能导入 v2rayN 吗？

不能。后缀不会改变数据语法、字段和规则含义。即使客户端能从 YAML 提取节点，也要单独确认策略组、路由和 DNS 是否被支持。优先使用提供方为目标客户端生成的格式。

Base64 订阅可以安全地公开分享吗？

不能把编码当成保密措施。Base64 内容可以还原，其中可能包含 UUID、密码、地址等连接信息。真实订阅及编码响应都应按敏感配置处理；公开泄露后，应按提供方支持的方式更换相关凭据。

两份配置都是 JSON，为什么还会提示 unknown field？

JSON 只规定一种数据表示方式，各核心的字段模型及版本要求不同。先从启动日志确认实际核心，再对照相应规范与迁移说明；语法能解析不等于核心能识别每个字段。

下一步：先识别数据属于订阅、节点还是完整配置，再确认目标软件与核心版本；只迁移能够核对的字段，保留原文件并逐项验证连接和分流。
