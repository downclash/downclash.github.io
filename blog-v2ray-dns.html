V2Ray DNS 设置与排查：节点解析、DoH、内网域名与 TUN

V2Ray DNS 解析失败，先检查什么？

先找到日志中解析失败的域名，再判断是谁在解析它。节点域名失败时查建立代理前的引导路径；目标域名失败时查核心 DNS、路由和上游可达性；只有开启 TUN 后失败时，再查接管与内网解析。直接换一个公共 DNS，不能同时修复这些不同问题。

  1. 固定节点、网络和目标，记录失败域名与报错时间。
  2. 区分系统、浏览器、核心以及远端承担的解析。
  3. 一次只改对应路径，重新请求目标并验证内网域名。

DNS 报错不一定是解析器太慢。节点服务器的域名、目标网站的域名、DoH 服务器自己的域名，可能在不同阶段由不同组件解析。本文适用于 v2rayN、v2rayNG、V2rayU 的诊断思路；具体字段必须对应实际运行的 V2Fly、Xray 或 sing-box 版本。

V2Ray DNS 的系统、节点与目标解析路径

系统与应用 DNS：浏览器可能启用自身的安全 DNS，其他应用可能使用操作系统配置；系统工具查询成功，只能说明该次系统查询成功。节点引导解析：客户端要先知道服务器地址，才能建立代理。核心目标解析：核心可能因路由匹配或出站连接需要解析目标，远端服务器也可能承担其中一部分。

因此，更改 Wi-Fi 的 DNS 不一定改变核心的查询；打开 DoH 也不等于每个应用的所有解析都走它。先从错误日志找到失败的域名、组件和发生时间，才能确定应修改哪层。

DNS 报错时需要记录哪些信息？

  1. 记下客户端、核心版本、当前网络与接管方式。保存原有系统和核心 DNS 设置。
  2. 选一个目标网站，保持同一个节点和路由配置，在直连、显式代理或 TUN 下分别复现必要的对照。
  3. 观察错误是服务器域名无法解析、DNS 上游连接超时，还是目标有地址后连接失败。
  4. 需要时暂时提高客户端支持的日志级别，只复现一次，再恢复原级别。日志可能包含个人域名与连接信息，分享前脱敏。

若使用系统查询工具，只将结果当作系统路径的证据。不能因为 nslookup 有结果，就断定使用远端 DNS 的代理核心也一定正常。

节点域名和 DoH 上游解析回环怎么处理？

如果节点地址是域名，而用于解析它的 DNS 必须经过同一条尚未建立的代理，就可能在启动时反复等待。另一个循环是 DoH 上游本身采用域名，而解析该上游又依赖它自己。先确认客户端为引导查询准备的解析路径，并核对该路径在当前网络可达。

不要随意把节点域名永久替换成网上找到的 IP：地址可能变化，TLS 服务器名称仍需正确，服务也可能依赖域名路由。确需静态映射，应由配置提供方给出有效参数，记录来源和恢复方式。Xray 的普通 DNS 上游与带 +local 的模式在路由路径上有区别，不能只因名字相似互换。

DoH、IPv4/IPv6 与 DNS 分流如何核对？

DoH 通过 HTTPS 传递 DNS 查询，仍依赖到上游的网络路径、域名引导和正常证书验证。上游能否直连或应走代理，必须符合当前配置。出现 TLS 错误，应检查时间、服务器名称和证书，不通过关闭验证来掩盖它。

Xray 的 DNS 说明指出，routing.domainStrategy 决定路由阶段是否需要把域名解析成 IP；DNS 的查询策略则控制允许的地址类型。两者不是同一个开关。只允许 IPv6 查询但当前链路没有相应可达性，或者全局与单个上游的查询类型相互限制，都可能造成意外结果。

sing-box 的 DNS 服务器结构与规则动作随版本演进，旧的字符串服务器示例未必适用于新版。优先通过 GUI 支持的选项修改，参考对应版本迁移文档；不要在客户端生成文件里改一次就假定下次启动仍有效。

修改 DNS 后怎样验证和恢复？

修改后，重建目标连接，用同一个网站和同一个应用验证，再检查直连站点与需要访问的内网域名。缓存可能使旧连接暂时不表现新设置，所以记录测试时刻和新请求比只刷新一个已有标签更可靠。

如果没有改善，恢复原值，再测试下一项。公司内部名称通常依赖专用解析器，不能全部交给公共 DNS。对“DNS 泄漏”的判断也应说明观测的是哪个应用、哪条查询路径；单个网页测试并不能证明所有系统流量的处理方式。

V2Ray DNS 设置常见问题

系统 nslookup 有结果，能证明代理 DNS 正常吗？

不能。系统查询、浏览器安全 DNS 和核心内置 DNS 可能走不同解析器与出站。系统查询成功可以作为对照，仍需检查代理日志中的具体查询和实际目标请求。

启用 DoH 就能避免所有 DNS 问题吗？

不能。DoH 仍需要上游可达、正确的引导解析和证书验证，也不保证所有应用都使用它。若上游域名的解析依赖尚未建立的同一代理，仍可能形成循环。

公司域名无法解析，可以统一换成公共 DNS 吗？

通常应先保留并核对企业指定的解析路径。内部名称可能只在公司 DNS 中存在，把它交给公共解析器不会得到所需结果。结合私有域名规则与企业 VPN 验证，再调整具体设置。
