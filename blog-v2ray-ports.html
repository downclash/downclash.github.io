v2rayN 本地端口怎么查：HTTP、SOCKS 与端口占用排查

v2rayN 本地端口应从当前配置查询，不能套用固定数字。按 HTTP、SOCKS 或混合入口核对应用设置，用 Windows、macOS、Linux 只读命令定位占用，再验证新端口。

v2rayN 本地端口在哪里查，冲突时怎么办？

先从客户端设置读取监听地址、端口和协议，再用系统命令确认哪个进程正在监听。本地 HTTP、SOCKS 或混合端口是应用交给代理的入口，和远端节点端口不同。确认占用者之后，正常关闭不再使用的程序或调整本地端口，并同步更新依赖它的应用。

  1. 读取真实入站信息，避免把示例端口或控制 API 当作代理端口。
  2. 使用 Get-NetTCPConnection、lsof 或 ss 查看监听与进程。
  3. 修改后用显式代理请求复测，不强行结束不认识的进程。

“本地端口”是其他程序把请求交给代理客户端的入口；节点的服务器端口是客户端连接远端服务的位置。二者可以完全不同。本文面向 v2rayN 和同类桌面客户端，帮助确认 HTTP / SOCKS / 混合入口与端口冲突；Android VPN 模式的正常使用不需要照搬桌面系统代理端口。

v2rayN 本地 HTTP、SOCKS 和混合端口在哪里看？

打开客户端设置中的本地监听、端口或入站相关项目，记下监听地址、协议、端口及是否允许局域网连接。不要把教程中的 10808、10809 或其他数字当作所有版本默认值。部分构建使用混合入口，其他构建将 HTTP 和 SOCKS 分开；是否兼容由实际运行的核心和配置决定。

还要区分控制 API、统计接口和代理入口。控制面板的端口不是浏览器应该填写的 HTTP 代理端口，不应为了连接方便把控制接口暴露给局域网。读取设置后，再通过监听状态判断这份配置有没有真正加载。

Windows、macOS、Linux 如何查询端口占用？

以下示例统一假设要检查 TCP 10809，它只是演示值，必须替换。命令仅查看信息，不会修改网络或结束进程。进程信息显示范围取决于当前账号权限；查不到进程名不等于不存在监听。

Windows PowerShell

Get-NetTCPConnection -State Listen -LocalPort 10809 |
  Select-Object LocalAddress, LocalPort, OwningProcess

按 Microsoft 命令说明查看并记下 OwningProcess 的进程号，再把下面的 1234 替换为实际值：

Get-Process -Id 1234

macOS

lsof -nP -iTCP:10809 -sTCP:LISTEN

Linux

ss -ltnp 'sport = :10809'

预期看到与客户端配置相符的地址、端口和程序。只监听 127.0.0.1 适合本机应用；监听 LAN 地址或全接口时，应额外核对访问边界。如果客户端报 UDP 端口冲突，要检查相应 UDP 套接字，不能只用 TCP 结果作结论。

端口未监听、代理协议错误和节点故障怎么区分？

没有监听时，先看核心是否启动、配置是否保存、是否被其他模式覆盖。不能只因为 GUI 窗口还在，就认为核心必定运行。出现 address already in use 时，说明绑定遇到占用；可能是另一个客户端，也可能是上一次启动留下的同一服务。

端口存在却不能用，还需要核对协议。HTTP 代理入口、SOCKS 入口和原始远端节点协议不能任意互换。若客户端提供兼容混合入口，应按该构建文档判断，而非凭端口名称推断。

本地握手成功之后仍有远端超时，则问题已经进入节点、DNS 或路由层。此时随机换本地端口通常不会修复服务器不可达。

用 curl 验证 HTTP 与 SOCKS 本地端口

选一个自己要验证的 HTTPS 目标，并用真实代理端口替换示例。Windows 可使用 curl.exe。下面两条分别演示 HTTP 与 SOCKS，选择与入口匹配的一种即可：

curl --noproxy "" --proxy http://127.0.0.1:10809 --head --max-time 15 https://example.com
curl --noproxy "" --proxy socks5h://127.0.0.1:10808 --head --max-time 15 https://example.com

--noproxy "" 用于本次显式代理测试，避免环境中的 NO_PROXY / no_proxy 绕过列表使请求改走直连；它不会改变客户端路由规则。

按 curl 的代理参数说明，socks5h 表示由 SOCKS 代理处理目标域名解析；它与本机先解析的测试路径可能不同。观察 curl 返回、核心日志中的目标与出站，再判断连接进行到了哪里。某些站点不支持 HEAD 或返回业务状态码，收到 HTTP 响应本身也不等于目标业务已完全可用。

v2rayN 端口占用的处理步骤

  1. 确认占用者属于哪个程序，查看它是否仍在使用。不结束不认识的进程，不使用批量强制结束命令。
  2. 若是自己不再使用的另一个代理，通过它的正常退出或停止服务入口关闭。
  3. 必须并行运行时，在当前客户端选择一个未占用且被系统允许的本地端口，保存并按要求重新加载。
  4. 重新检查监听，再同步修改系统代理、浏览器、终端环境变量和其他应用中手写的旧端口。
  5. 用同一目标复测，记录新旧值。端口无人占用仍绑定失败时，继续核对系统保留范围、地址是否存在及安全软件记录。

端口修改后怎样恢复代理设置？

不继续使用时，清除这次客户端设置的系统代理，停止 TUN 后再退出。恢复旧端口前先确认它仍可用，并同步恢复依赖它的应用。若原来就有企业代理，恢复原始记录；不要为了清理测试而覆盖组织设置。

v2rayN 本地端口常见问题

v2rayN 一定使用 10808 和 10809 吗？

不一定。端口随版本、配置和用户修改而变化，HTTP 与 SOCKS 也可能共用混合入口。以客户端当前设置和系统监听结果为准，文中的数字只用于演示命令。

端口存在，为什么 curl 还是连接失败？

存在监听只说明有程序接受该地址的连接，还要核对它是否属于预期客户端、代理协议是否匹配。若请求已经进入核心，再看 DNS、活动节点和远端握手，而不是不断更换本地端口。

提示端口被占用，可以直接强制结束那个进程吗？

先确认进程用途和依赖，不结束不认识的程序。自己不再使用的代理可通过正常入口停止；必须并行运行时选择未冲突的新端口，并更新系统代理、终端与其他应用中的旧值。
