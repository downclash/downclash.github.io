先区分协议、传输与安全层

例如“VLESS + WebSocket + TLS”描述的是一组配套设置。VLESS 负责代理协议与用户认证，WebSocket 是承载方式，TLS 处理传输安全。REALITY 属于传输安全配置；gRPC 与 WebSocket 属于传输方式，它们都不是可直接替换 VMess、VLESS 的节点类型。

层次常见名称需要匹配的内容
代理协议VMess、VLESS、Trojan、Shadowsocks协议类型、UUID 或密码、加密方式
传输方式RAW / TCP、WebSocket、gRPC服务端支持的传输、路径或 serviceName
传输安全TLS、REALITY服务器名称、证书校验，或公钥与 short ID 等
本机接入HTTP / SOCKS 监听、系统代理、TUN / VPN应用如何把流量送入客户端

组合必须由服务端实际配置决定。只把客户端的传输改成 gRPC，或只勾选 REALITY，不会让原节点自动升级。

六类常见代理协议怎样识别

VMess：核对 UUID 与系统时间

VMess 是 V2Ray 生态的代理协议，节点通常以 vmess:// 分享。除服务器地址、端口与 UUID 外，还要核对传输与 TLS 设置。它的认证依赖系统时间；遇到认证失败时先启用设备的自动日期与时间，再检查节点参数。旧配置中的额外认证字段应以当前服务端说明为准。

VLESS：基础协议相同不等于扩展相同

vless:// 节点常包含 UUID、传输、安全层和 flow。常见 encryption=none 配置需要匹配服务端的 TLS 或 REALITY；不能将其理解成数据无需保护。Xray 新版本还包含独立的 VLESS Encryption 配置，不能把这些扩展直接套用到其他内核。Vision、REALITY 与新加密字段都要逐项核对支持情况。

Trojan：密码与 TLS 配置一起核对

Trojan 节点通常通过密码认证，并配合 TLS 使用。服务器地址可以与用于证书校验的服务器名称不同，因此应保留提供者给出的 SNI / serverName。握手失败时检查系统时间、服务器名称和证书链，继续保留证书验证。

Shadowsocks：加密方法也是协议参数

ss:// 节点需要服务器、端口、密码与加密方法。不同代际的方法及插件要求可能不同；支持 Shadowsocks 不代表支持所有加密方法与插件。导入失败时先检查当前客户端和内核支持的具体 method，而不是任意更换加密算法。

SOCKS 与 HTTP：分清本机端口和远程节点

它们既能作为本机接收应用流量的入口，也能作为远程代理出站。例如浏览器连接 127.0.0.1 的 SOCKS 端口，是把流量交给本机客户端；真正访问远端时仍由所选出站节点处理。SOCKS5 本身不提供链路加密，HTTP 代理也不能因为目标站使用 HTTPS 就被视为所有代理通信都已加密。

导入后核对哪些参数

  1. 检查服务器地址与端口，区分连接地址和 TLS 服务器名称。
  2. 保留完整的认证信息：UUID、密码、加密方法，以及节点要求的 flow。
  3. 核对传输类型；WebSocket 的 path / Host、gRPC 的 serviceName 不能互相替代。
  4. TLS 节点核对 SNI 与证书；REALITY 节点核对公钥、short ID、指纹和服务端要求的其他字段。
  5. 选择支持该组合的内核，再测试实际目标站点。单次 TCP 延迟只说明服务器端口可能可达。

分享链接、二维码和订阅 URL 可能含密码、UUID 或 token。向他人求助时隐藏这些字段，并保留报错类型、协议、传输与内核版本。
