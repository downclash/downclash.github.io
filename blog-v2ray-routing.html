V2Ray 规则分流教程：域名、IP、GeoData 与出站顺序

V2Ray 规则分流通过域名、IP 和 GeoData 匹配出站。结合 v2rayN 设置与 Xray 路由片段理解规则顺序、出站标签和默认行为，并用新连接验证直连、代理与拒绝结果。

V2Ray 规则分流不生效，怎样定位？

先确认请求已进入核心，再检查活动规则、匹配顺序和出站标签。Xray 常规规则按顺序寻找首条匹配项；前面的宽泛规则、错误的域名写法或未加载的 GeoData 都可能改变结果。修改后用一条应匹配和一条不应匹配的请求核对出站。

  1. 记录核心与活动路由模式，备份当前规则。
  2. 检查实际目标是域名还是 IP，以及解析策略是否满足匹配条件。
  3. 通过客户端支持的入口保存并重新加载，再用日志确认出站。

规则分流回答的是：核心收到一条连接后，应该从哪个出站发送。本文以 Xray 的字段讲解，供 v2rayN、v2rayNG 等客户端理解配置；V2Fly 和 sing-box 应对照各自文档。开始前先确认节点本身可用，再改规则，避免把连接故障误判为分流问题。

V2Ray 分流中的入站、规则和出站是什么？

系统代理或 TUN 把请求送进来；路由读取目标域名、IP、端口等条件；出站负责直连、节点代理或拒绝。给某个网站设置代理规则，并不能让原本没有进入核心的应用自动受到这条规则影响。

按Xray 路由文档的常规规则机制，规则从上到下寻找首条匹配项；未匹配时使用第一个出站。客户端的“全局”“绕过局域网”等模式可能生成不同规则和出站顺序，必须核对当前生效配置，不能只凭规则列表里有一个域名就判断它会被命中。

域名、IP、GeoIP 与 Geosite 规则怎么匹配？

  • 域名：Xray 的 domain:example.com 匹配该域名与子域名；精确单域名可查看 full: 写法。需要留意“子域名”与任意字符串包含不是一回事。
  • IP / CIDR：匹配实际 IP 或地址段。域名目标是否先被解析为 IP，受路由的解析策略与请求所携带的信息影响。
  • GeoIP / Geosite：引用数据文件中的 IP 或域名分类。分类名称、文件来源和核心格式都要匹配，不能把其他软件的规则集只改后缀使用。
  • 多个条件：同一条 Xray 规则中不同属性通常要同时满足。例如同时填写域名和端口时，不是任选一个符合就匹配。

应用连接一个网站还可能访问登录、静态资源、图片和 API 等其他域名。首页命中代理不等于所有后续请求都走同一路径，排查时观察真正失败的那条连接。

Xray routing 规则结构示例

下面只演示 routing 结构，没有入站、出站和节点参数，不能独立运行，也不能直接替换客户端完整配置。example.com、网段和两个出站标签都是演示值；标签必须对应完整配置中已存在的出站。

{
  "routing": {
    "domainStrategy": "AsIs",
    "rules": [
      {
        "type": "field",
        "domain": ["domain:example.com"],
        "outboundTag": "proxy-example"
      },
      {
        "type": "field",
        "ip": ["192.168.50.0/24"],
        "outboundTag": "direct-example"
      }
    ]
  }
}

第一条把示例域名交给 proxy-example；第二条匹配示例私有网段。AsIs 不为 IP 分流主动解析域名，所以“只提供域名、尚无原始 IP”的请求不能仅因最终可能解析到该网段，就被认为一定会命中第二条。需要域名转 IP 匹配时，再研究对应的解析策略和 DNS 路径。

v2rayN 自定义路由的修改与验证步骤

  1. 备份当前路由与配置，记录活动规则模式、核心版本及一个可复现目标。
  2. 优先使用客户端的路由编辑或自定义配置入口。直接改它生成的临时 JSON，可能在订阅更新、切节点或重启后被覆盖。
  3. 只添加一条必要规则，并放在会覆盖它的宽泛规则之前。保存并按客户端要求重新加载。
  4. 重新发起目标请求，在日志或连接视图中核对目标、规则或出站标签；界面不显示规则名时，使用支持的访问日志判断出站。
  5. 再请求一个不应匹配的目标，确认默认行为和内网访问仍符合预期。

从 Xray 切换到 sing-box 后，应按sing-box 路由规则文档使用 route 及其版本对应的规则与动作，不能照搬这里的 routing.rules。GUI 是否能为多个核心生成等价规则，应由实际请求验证。

路由修改失败后怎样恢复？

修改导致核心无法启动时，恢复上一次可用规则，再核对报错字段。更新 GeoData 后出现变化，应保存数据版本与分类名，避免用临时宽泛规则长期掩盖问题。每次修改记录目标、预期出口和实测结果，方便升级后复查。

V2Ray 规则分流常见问题

添加了域名规则，为什么请求还是走别的出站？

先看请求是否进入核心，以及是否命中了更靠前的规则。再核对客户端当前启用的路由模式、实际失败域名和配置是否被重新生成。规则存在于编辑列表，不等于它已在运行配置中生效。

域名最终解析到内网，IP 直连规则一定会命中吗？

不一定。要看原始目标信息和路由解析策略。以 Xray 的 AsIs 为例，它不会为了 IP 分流主动解析一个仅有域名的目标；还需区分系统 TUN 排除与核心直连。

Clash 的规则可以直接粘贴到 Xray 或 sing-box 吗？

不能直接照搬字段。Clash YAML、Xray 的 routing 和 sing-box 的 route 有各自结构与版本要求；分类数据的格式也可能不同。应按目标核心重建规则，并用相同请求验证实际行为。
