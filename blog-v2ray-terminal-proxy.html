v2rayN 终端代理教程：curl、环境变量与 SOCKS DNS

v2rayN 终端代理可先用 curl 显式参数验证，再为指定进程设置临时环境变量。区分 HTTP、socks5 与 socks5h，排除 NO_PROXY 干扰，并核对 SSH、WSL 和容器中的请求位置。

v2rayN 终端代理怎么设置？

先在 v2rayN 中确认实际 HTTP 监听端口，再用 curl 显式指定这个入口；请求成功并且日志出现预期连接后，才给需要的工具设置环境变量。浏览器的系统代理不能证明终端程序也已使用代理。

curl --noproxy "" --proxy http://127.0.0.1:10809 --head https://example.com

10809 是示例端口，需替换；Windows PowerShell 可使用 curl.exe。这次请求显式清空绕过名单，避免已有 NO_PROXY 影响测试。

打开 v2rayN 的系统代理后，浏览器能联网，并不表示终端中的每个程序都会读取同一设置。终端只是启动程序的环境：curl、Git、Python 和包管理器分别决定是否读取代理参数或环境变量。下面先验证一条请求，再把设置限制到一次命令或一个子 shell，便于判断问题。

确认 v2rayN 的 HTTP / SOCKS 监听端口

本教程适用于已经启动 v2rayN 或其他兼容客户端的 Windows、macOS 和 Linux。先在客户端设置中找到真实的 HTTP、SOCKS 或混合监听端口，确认活动节点可用；不要把远程服务器端口填成这里的本地端口。示例中的 10809 与 10808 仅用于说明，必须改成自己的值。

如果在 SSH、WSL 或容器内运行命令，还要确认命令所在的机器。那里的 127.0.0.1 指向该环境自身，未必是运行桌面客户端的电脑。先在客户端所在的系统中完成一次测试，再研究跨环境访问，避免同时改变多个条件。

用 curl 验证终端 HTTP 代理

先执行以下请求。Windows PowerShell 建议使用 curl.exe，以免调用到同名别名；macOS / Linux 使用 curl。example.com 是测试用示例域名，可替换为你有权访问的实际目标。

curl --noproxy "" --proxy http://127.0.0.1:10809 --connect-timeout 10 --max-time 20 --head https://example.com

--noproxy "" 让这次测试不被已有绕过名单跳过；http:// 描述的是本机代理入口，目标仍然可以是 HTTPS。对 HTTPS 目标，HTTP 代理通常通过 CONNECT 建立隧道，不能因为目标是 HTTPS 就把本机普通 HTTP 入口改写成 https://。

同时观察客户端日志：应出现这次目标连接及其出站。看到 HTTP 响应说明请求走到了某个响应端；403、429 或登录页面仍需按目标服务的权限和限流解释。若服务不允许 HEAD，可改用实际 GET 请求复测，不能仅凭 HEAD 被拒绝认定代理失效。

socks5 与 socks5h 的 DNS 解析有何区别？

客户端提供 SOCKS5 时，可用对应端口测试。以下写法把目标域名交给 SOCKS 代理解析：

curl --noproxy "" --proxy socks5h://127.0.0.1:10808 --connect-timeout 10 --max-time 20 --head https://example.com

curl 中 socks5:// 与 socks5h:// 的区别涉及目标域名由哪一端解析，后者由代理端处理。curl 的代理参数说明明确区分这些 SOCKS 类型。它不等于“整台电脑的 DNS 都经过代理”，也不决定远程代理服务器域名如何被客户端解析。出现解析错误时，应先区分这两个域名，再检查对应解析路径。

在 Bash / Zsh 中临时设置代理环境变量

确认显式请求正常后，macOS / Linux 的 Bash 或 Zsh 可以在子 shell 中给支持这些变量的程序传递代理。括号里的设置在子 shell 退出后结束，既不改启动配置文件，也不覆盖父 shell 的原设置。

(
  export http_proxy=http://127.0.0.1:10809
  export https_proxy=http://127.0.0.1:10809
  export no_proxy=localhost,127.0.0.1,::1
  curl --head https://example.com
)

curl 对 HTTP 代理变量有大小写规则，在区分大小写的系统中应使用小写 http_proxy。ALL_PROXY 是未指定对应协议代理时的候选，不一定覆盖 https_proxy。其他工具的读取规则可能不同，因此不要把这段设置当作对所有开发工具的统一配置。变量优先级与大小写规则可对照 curl 环境变量说明。

暂时不要把 export 写进 shell 启动文件。长期配置前先确认客户端能随需要运行，并保留原有变量值及绕过企业内网的要求。代理地址若包含凭据，不应直接写进公开脚本或发到聊天记录。

curl 连接失败：按错误定位

现象先检查应看到的结果
立即 connection refused客户端是否运行、协议和本机端口是否正确本机入口能够接受连接
显式代理正常，环境变量无效工具是否读取变量、是否存在工具自身代理和绕过名单同一请求出现在客户端日志中
SOCKS 域名解析失败区分本机解析与代理解析，确认节点和目标域名解析完成后进入握手或目标响应阶段
本机正常，容器或远程终端失败请求进程所在机器与回环地址使用该环境实际能到达的受控代理入口
HTTP 有响应但证书失败系统时间、目标名称和所需的可信证书链保留证书校验并完成 TLS 验证

结束终端代理测试与恢复原配置

显式 --proxy 只影响这次命令；子 shell 示例在结束时自然恢复。若此前手动写过启动文件，应只移除自己添加的条目，重新打开终端并检查，不要清空整个企业代理配置。关闭客户端之前先停止依赖它的测试请求，按客户端正常关闭系统代理或 TUN。

需要对照“未指定应用代理”的请求时，可以使用 curl --noproxy '*' --head https://example.com；但开启 TUN 时，这个请求仍可能被系统路由接管，不能把它直接当作物理网络直连结果。最终验证应同时记录命令参数、接管方式和日志出站。

终端代理常见问题

设置了 https_proxy，为什么 curl 仍没有进入客户端？

先检查命令是否运行在预期机器上，再核对本地协议和端口，以及 no_proxy / NO_PROXY 是否匹配目标。用上方带 --noproxy "" 的显式请求做对照，并检查日志；其他工具仍需分别验证自己的代理规则。

socks5h 会让整台设备的 DNS 都经过代理吗？

不会。它指定的是这次 curl 请求的目标域名由 SOCKS 代理解析。系统、浏览器或其他进程可以继续走自己的 DNS，客户端解析远程节点地址的路径也需要单独核对。

关闭终端能恢复代理环境变量吗？

本文的子 shell 示例结束后不会改变父 shell。若你把 export 写进了启动文件，新终端仍会加载它；应恢复自己修改的条目，并保留原有企业代理与绕过名单。显式 --proxy 参数则只影响一次命令。
