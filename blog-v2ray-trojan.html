Trojan 节点配置教程：密码、TLS、SNI 与传输兼容检查

Trojan 节点配置要同时核对密码、服务器地址、TLS、SNI 和传输类型。按 v2rayN、v2rayNG 或 V2rayU 的实际内核检查导入结果，定位证书、认证和连接错误，保留证书验证。

Trojan 节点怎么配置并验证？

导入 Trojan 订阅或节点链接后，先核对远端地址、端口、密码、TLS 名称和服务端要求的传输，再设为活动节点。开启对应的代理入口，用真实请求检查 TLS、认证与目标响应；出现证书错误时修正原因并保留验证。

  • 连接超时先查地址、端口与解析。
  • TLS 错误先查时间、SNI、证书与节点来源。
  • 握手后失败再核对密码、传输和服务端兼容要求。

Trojan 节点通常把身份认证放在 TLS 连接中完成。拿到节点后，既要检查密码，也要检查连接地址、服务器名称与传输方式；“端口是 443”并不意味着配置一定正确。本教程针对已有节点的客户端配置，不指导创建服务端。

Trojan 节点需要核对哪个客户端与内核？

v2rayN、v2rayNG 和 V2rayU 是配置界面，真正处理 Trojan 的是运行中的内核。先记录它的名称与版本，再看提供方给的是通用节点链接、某种核心 JSON，还是包含完整路由的订阅。相同的 Trojan 协议不代表所有传输扩展和复用方式都能跨核心照搬。

V2Fly、Xray、sing-box 分别提供 Trojan 出站说明。它们组织 JSON 字段的方式不同，GUI 还可能在启动时重新生成配置。使用 Xray 时可对照其 Trojan 出站文档核对字段，其他内核查相应文档。优先使用客户端支持的导入方式，手工参数只用于核对，不把另一内核的完整配置直接覆盖到当前目录。

Trojan 密码、TLS 与 SNI 怎么填写

项目填写依据容易混淆的内容
服务器地址与端口节点提供方的实际入口端口可以不是 443，本机 HTTP / SOCKS 端口不是远端端口
密码原配置中的完整密码它不是 VMess UUID，也不是 TLS 证书私钥
TLS 名称 / SNI服务端接受且证书适用的名称连接 IP 与 TLS 名称可能不同，不随意填常见网站域名
传输及扩展服务端指定的 WebSocket、gRPC、封装或复用设置不能从节点备注推断这些参数，也不能只改客户端让服务端跟随改变

密码含特殊字符时，分享链接需要正确编码。导入后发现长度、符号或尾部不一致，优先重新获取完整链接；不要在在线网站上反复转码真实密码。将密码展示为星号也不代表导出的配置或二维码已经脱敏。

Trojan 订阅导入与第一次连接步骤

  1. 保留现有可用配置与原始节点来源，确认设备本身能联网。
  2. HTTP(S) 订阅添加到订阅管理并更新；trojan:// 节点链接从剪贴板、二维码等对应入口导入。
  3. 在节点编辑信息中核对密码、远端地址、TLS 和传输要求，保存提供方给出的附加选项。
  4. 把该节点设为活动节点，启动核心。桌面端开启适合的代理入口；Android 允许 VPN 连接。
  5. 请求同一个 HTTPS 页面，再看核心日志里该请求经过的出站和错误阶段。

如果列表里有多个相同名称，给测试副本添加能区分的备注。这样测速、选中节点和最终请求更容易对应，不会因为导入成功却仍使用旧节点而误判。

Trojan 证书验证失败时先修正什么

V2Fly Trojan 文档说明其应运行在正确配置的 TLS 隧道中。发生证书错误时，先核对系统日期与时间，再看证书要求的名称是否与 SNI 一致，最后确认配置来源是否更新了入口或证书。按提供方说明使用私有 CA 的场景，需要核对其信任配置，不能将不认识的证书随意设为系统信任。

不要勾选“跳过证书验证”作为长期修复。即使请求暂时能打开，也无法确认连接端身份正确。若底层日志显示根本未到达 TLS 阶段，优先查 DNS、地址与端口，而不是修改密码或证书设置。

Trojan 连不上：按错误阶段检查

现象优先检查验证结果
导入后字段为空链接是否完整、导入入口是否支持格式地址、密码和安全参数能正确保存
域名错误或超时节点域名解析、远端端口、网络路径能进入 TLS 握手
证书不匹配或不受信时间、SNI、证书链和提供方说明启用验证时仍能完成握手
认证失败或握手后断开密码、传输、服务端兼容要求目标请求通过当前出站完成
网页可用，语音或游戏不通应用流量入口与端到端 UDP 支持单独验证受影响业务，不能用网页替代

复用、传输扩展与 UDP 封装都有版本和对端要求。保持配置提供方的适配值，不将某个开关当作所有 Trojan 节点的通用提速方案。需要升级时同时核对客户端与实际内核，而非仅比较界面版本号。

Trojan 配置修改后的对照与恢复

只改变一项已确认错误的设置，重新建立连接并复测。无改善就恢复，避免同时改密码、DNS、TUN 与路由。若所有 Trojan 节点失败，但其他协议可用，记录它们是否共享同一入口、网络与证书条件，再交给配置提供方进一步核对。

退出使用时清除系统代理或断开 VPN。反馈材料保留失败时间、系统、客户端和内核版本，删除密码与完整订阅；普通的截图备注也可能包含用户标识。具体的接管和日志排查可继续查阅相关教程。

Trojan 节点常见问题

Trojan 节点一定使用 443 端口吗？

不一定。远端端口由服务端配置决定，应填写提供方给出的实际值；443 只是常见选择之一，不能凭协议名替换导入的端口。还要区分远端端口与本机 HTTP / SOCKS 监听端口。

Trojan 密码与 VMess UUID 可以互换吗？

不能。它们属于不同协议的认证参数，客户端必须使用当前节点认可的身份。导入后密码缺失或符号变化时，重新获取完整链接，不拿其他节点的身份字段代替。

同一个 Trojan 节点换内核就一定能用吗？

不一定。基本协议之外还可能有传输、复用或 UDP 封装要求，客户端也可能无法完整导入新字段。换内核前核对双方文档与提供方配置，保存原设置后再验证实际连接。
