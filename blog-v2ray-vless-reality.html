VLESS + REALITY 配置教程：导入节点、核对参数与连接验证

VLESS + REALITY 怎么配置？

先确认实际运行的 Xray 或 sing-box 支持节点要求，再导入提供方的订阅或分享链接，核对服务器、身份、传输和 REALITY 认证四组参数，最后用真实请求验证。只导入成功或延迟测试正常，都不能说明 REALITY 握手已经通过。

  1. 记录客户端与实际内核版本，保留原始配置。
  2. 核对 UUID、flow、SNI、客户端凭据和 short ID，保持服务端要求的组合。
  3. 设为活动节点并重新连接，对照目标请求、出站和错误日志。

已经拿到一个 VLESS 节点，却不知道 REALITY、公钥、flow 应该填在哪里？本教程面向已有可用配置的客户端用户，重点是导入后核对与验证，不包含服务器搭建。使用 v2rayN、v2rayNG 或 V2rayU 前，先确认客户端所调用的内核支持提供方要求的组合。

VLESS + REALITY 需要什么内核与传输？

VLESS 是代理协议，REALITY 是传输安全机制，WebSocket、gRPC 或 RAW / TCP 则属于承载连接的方式。它们不是三个可以随意替换的节点类型。列举传输种类不表示每一种都能与 REALITY 组合，可用组合须以当前内核文档和服务端配置为准。分享链接里写有 vless://，也不能据此推定所有客户端都能识别该链接中的新字段。

在客户端日志或版本说明中记录实际启动的 Xray、sing-box 及其版本，再核对节点所需功能。Xray 已有 VLESS Encryption 扩展，不能把所有 VLESS 都概括为固定的 encryption=none；也不能把 Xray 的完整出站 JSON 原样塞进 sing-box。有关扩展及其限制，见 Xray VLESS 出站文档。

VLESS + REALITY 节点参数：四组信息怎么核对

参数组需要核对什么常见误填
服务器与身份连接地址、端口、UUID / 用户 ID把展示名称当地址，或把客户端本地端口当远端端口
协议与流控VLESS、加密扩展设置、flow只因看到 REALITY 就自行添加 Vision；服务端未要求却改变 flow
承载方式提供方指定的传输及其附加参数把旧版 TCP 名称与新内核命名差异当作服务端配置变化
REALITY 认证服务器名称 / SNI、客户端持有的凭据、short ID 与指纹要求使用随机网站名称、漏字符、把服务端私钥粘到客户端

同一个概念在界面与内核里可能使用不同标签。例如当前 Xray 文档将 REALITY 客户端凭据写作 password，并注明旧称 publicKey；sing-box 文档仍使用 public_key。这里要填的是配置提供方给客户端的值，不能根据字段改名自行生成或换成服务器私钥。字段更名依据见 Xray REALITY 客户端参数说明，sing-box 则应查其 TLS 文档。

在 v2rayN / v2rayNG 导入并核对 VLESS 节点

  1. 保留原始订阅或分享链接，另存当前可用配置。订阅地址添加到订阅管理；单节点分享链接使用节点导入入口。
  2. 导入后找到节点编辑页面，对照提供方参数逐组检查。只看节点备注或地区旗帜无法确认字段完整。
  3. 确认 REALITY 已作为安全方式启用，并核对 SNI、short ID 与客户端凭据。short ID 的格式和是否允许留空都以服务端及对应内核说明为准。
  4. 保持提供方给出的指纹、flow 与扩展参数。没有字段入口时，先查该客户端版本是否支持；不要用一个“看起来相近”的字段替代。
  5. 保存并将节点设为活动节点，停止旧连接后重新启动，再读取首个核心错误。

如果订阅更新会覆盖节点，手工测试请使用客户端支持的副本或独立配置，避免改完立刻被自动更新还原。手工修改前记录字段名与旧值；完整分享链接和 REALITY 凭据都按敏感配置保管。

如何确认 REALITY 节点已经实际连接

先确认核心成功启动，再开启适合当前设备的系统代理或 VPN。打开一个预期走代理的 HTTPS 页面，核对请求是否进入日志、是否选择当前 VLESS 节点，以及远端握手是否成功。桌面端浏览器成功后，再单独测试实际要使用的应用。

TCP 延迟正常只证明测试路径的部分可达性，不代表 REALITY 认证已经通过。反过来，没有任何目标请求进入日志，通常应先查流量入口，而不是重新生成 UUID。测试同一个目标并记录时间，便于把浏览器结果与日志对应起来。

REALITY 握手失败与未知字段怎样排查

现象优先检查通过标准
未知字段、无法启动实际内核版本、生成配置与导入能力核心加载配置并监听本机入口
连接地址解析失败或超时节点域名、远端端口、当前网络可达性连接能够进入安全握手阶段
REALITY 握手或认证失败SNI、凭据、short ID、指纹与服务端要求完整握手后目标请求获得响应
只有个别目标失败路由、DNS、目标服务与出口要求区分节点故障和目标服务限制

修正 VLESS 参数后如何恢复与反馈

一次仅修正一个有依据的字段，并重建连接复测；无改善就恢复旧值。若升级后才出现问题，记录前后内核版本与原始错误，查发布说明后选择兼容配置。不要通过关闭验证、删掉 REALITY 或改成明文连接来掩盖握手失败。

求助时提供客户端、内核版本和脱敏后的错误阶段即可。隐藏节点身份、凭据和完整链接；需要服务端核对时，把失败时间和字段名称交给配置提供方。单纯换客户端之前，也应确认新软件支持相同功能。

VLESS + REALITY常见问题

没有 REALITY 参数入口，还能直接使用该节点吗？

不能仅凭协议列表里有 VLESS 就判断可以使用。先确认所装客户端能导入该节点的 REALITY 字段，实际内核也支持对应组合；入口缺失或字段丢失时，使用项目支持的适配方式或索取兼容配置，不用其他字段代填。

REALITY 与普通 TLS 可以在客户端随意切换吗？

不能。客户端安全方式必须与远端配置相符，只改一个开关不会让服务器同步切换。需要改用其他组合时，应取得提供方对应的新配置，再分别验证传输、身份与连接结果。

VLESS + REALITY 延迟正常，为什么网页仍打不开？

延迟测试可能只覆盖端口或某个测试目标。先看网页请求是否进入客户端，再核对当前节点、REALITY 握手以及 DNS 和路由；用同一目标的真实响应确认结果，而非只比较延迟数字。
