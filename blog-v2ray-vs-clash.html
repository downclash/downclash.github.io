厘清内核与客户端

V2Fly / V2Ray、Xray、sing-box 是不同的核心项目。v2rayN、v2rayNG、V2rayU 则提供安装、订阅管理、节点选择等界面；实际能力取决于集成的核心和版本。v2rayN 项目已明确支持 Windows、Linux、macOS，并列出 Xray、sing-box 等内核，不能再把它归为仅 Windows 的 V2Ray 外壳。

Mihomo 是当前 Clash 兼容生态中的核心之一，其文档覆盖节点、代理组、规则集、DNS 与 TUN。比较时应明确所用客户端及内核，而不是用旧版 Clash 的能力代替所有 Mihomo 客户端。已有 Clash 配置的用户也应核对其中的扩展字段和内核要求。

两种常见使用方式

以节点为中心：导入、选择、再配置路由

在 v2rayN / v2rayNG 这类客户端中，用户通常导入节点分享链接或客户端支持的订阅，选择活动节点，再选择路由方案与接管方式。节点记录主要描述如何连接服务器；仅有节点列表，不代表已经拥有完整的分流规则。

以配置为中心：节点、代理组和规则协作

Clash / Mihomo 格式配置常通过 YAML 描述节点、代理组、DNS 和规则，并可引用远程 provider。用户在代理组中选择或自动测试节点，由规则决定连接交给哪个组。不同客户端可能对订阅进行合并或覆写，因此要分清订阅原文与最终生效配置。

这两种工作流存在交集。部分客户端支持多种格式或自定义配置，但支持导入某类节点，不等于完整保留另一种配置中的 DNS、规则、策略组和扩展字段。

更换客户端前检查

  1. 保留原配置。备份节点和自定义规则，在新客户端完成验证后再切换日常使用。
  2. 确认订阅格式。优先向配置提供者获取目标客户端支持的格式，不能只更改链接后缀就假定完成转换。
  3. 逐项核对节点。地址、认证、安全层、SNI、传输、路径、flow 等字段都要保留；“导入成功”只证明解析器接受了输入。
  4. 重新核对规则与 DNS。节点导入一般不能证明代理组、域名规则、远程规则集和 DNS 策略已经等价迁移。
  5. 逐层验证。先让单个节点和目标网站可用，再验证本地服务直连、需要代理的应用以及 TUN / VPN。

订阅 URL 与节点链接可能包含账户凭据。需要转换时，应先确认工具来源与处理方式，避免把完整链接提交到不明在线服务。

如果新客户端中节点测速正常、应用却不能访问，先查接管方式和分流。具体检查顺序见常见问题与连接与速度排查。
