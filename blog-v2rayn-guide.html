v2rayN 使用教程：下载安装、订阅导入与系统代理 / TUN

按 Windows、macOS、Linux 选择 v2rayN 安装包，区分订阅与节点链接，完成活动节点、系统代理和 TUN 设置，并按日志排查连接问题。

更新于 2026-11-24 · 阅读约 8 分钟

资料整理：V2Ray 下载站 · 独立资料站，依据项目文档整理

v2rayN 是支持 Windows、Linux 和 macOS 的桌面图形客户端，可以调用 Xray、sing-box 等核心。客户端负责管理节点和生成配置，核心负责处理连接；同一客户端中切换核心后，可用的协议、路由与配置字段也可能变化。本教程以 Windows 的首次连接为主，其他桌面平台按相同顺序检查。

开始前准备：从可信来源取得兼容订阅或自建节点参数，确认设备能直接联网。客户端本身不附送节点。记录现有系统代理、VPN 和 DNS 设置，方便测试后恢复。

选择安装包与启动

先在下载中心核对系统与架构，再进入 v2rayN 项目 Releases。版本以发布页为准，下载 Assets 中的应用包，Source code 是源码归档。

设备选择依据启动时检查
Windows在系统“关于”中确认 x64 或 ARM64；系统要求按所选发布版说明核对。windows-64.zip 为 WPF 界面，desktop 为 Avalonia 界面。完整解压 ZIP，再运行主程序；不要在压缩包内启动。
macOSIntel 选 64 / x64；Apple 芯片选 arm64。最低系统要求按所选发布版核对；项目 Wiki 的 v8.x 要求不能直接套用到 7.x 稳定版。按Mac 下载说明选择 DMG 或 ZIP，核对当前版本的安装要求。
Linux按发行版选择 DEB、RPM 或 ZIP，并匹配 amd64 / ARM64 等架构；最低发行版要求见项目 Wiki。Linux 安装与系统代理教程提供按发行版核对的操作步骤。通过发行版包管理器安装，或按项目说明运行便携包。

ZIP 包通常把数据放在解压目录；升级前备份该目录中的配置。若启动提示缺少运行时，按所选版本发布说明安装对应架构的运行时，或选择项目提供的适用构建。不要将旧版的 .NET 要求套用到所有新版安装包。

导入订阅或单个节点

订阅 URL 通常是 https://…，用于获取和更新一组节点；vmess://、vless://、trojan:// 等分享链接描述单个节点。两者的导入入口不同。

  1. 订阅：打开“订阅分组”或“订阅设置”，新增分组，填写备注与完整 URL 后保存。
  2. 选中该分组，执行“更新当前订阅”。首次尚无可用代理时，优先尝试界面中的“不通过代理”更新选项。
  3. 确认列表出现节点，并核对数量、备注和协议是否符合预期。若返回登录页、错误页或不兼容格式，应向配置提供方取得适用链接。
  4. 单个节点：复制完整分享链接，使用“从剪贴板导入”入口；二维码应包含客户端可识别的节点或导入数据。导入后检查地址、端口、传输与 TLS 参数。

菜单名称可能随版本和界面框架略有变化，以相同功能入口为准。不要为了转换格式把含 token 的订阅上传到陌生网站；格式差异见配置文档。

选择节点与代理模式

  1. 在节点列表中右键选择目标节点，执行“设为活动服务器”，确认当前服务器标记已改变。
  2. 先使用系统代理：在“系统代理”中选择“自动配置系统代理”，再在路由中选择适用规则。系统代理决定哪些应用把流量交给核心，路由决定核心收到流量后如何转发。
  3. 查看日志，确认核心成功启动，没有端口占用、配置解析或 TLS 握手错误。此时再进行网页验证。
方式适用情况注意事项
系统代理主要使用遵循系统代理设置的浏览器或应用。终端、游戏及自带网络栈的应用可能需要另配代理。
TUN需要接管更多不读取系统代理的应用流量。依当前版本提示准备服务或所需权限；检查 DNS、路由及其他 VPN 冲突。
手动指定本地代理只给某个应用或命令使用代理。从客户端设置读取实际 HTTP / SOCKS 端口，不要照搬旧教程的默认值。

首次排查只启用一种接管方式。需要 TUN 时，先确认同一节点通过系统代理可连接，再按客户端提示开启 TUN。节点协议和核心必须匹配；不要把 VLESS、REALITY 或某个 sing-box 能力视为所有 V2Ray 核心通用功能。

验证连接与正确退出

  • 节点测试：运行客户端提供的延迟或真实连接测试；成功只说明测试路径可用，数值不能代表所有网站的速度。
  • 网页测试：访问需要代理的目标网站，同时打开一个应当直连的网站，结合日志核对两类请求的路由结果。
  • 应用测试：单独验证终端或目标软件。浏览器可访问而终端失败时，优先检查终端是否使用了正确的本地代理。
  • 退出：先关闭 TUN、清除由客户端配置的系统代理，再退出程序；确认正常直连恢复。若原本有企业代理，恢复预先记录的值。

按现象排查

现象先检查修复后的结果
无法启动 / 核心退出包的架构、解压是否完整、运行时提示、核心日志；有端口冲突时更换本地端口。核心保持运行，本地监听地址与设置一致。
订阅更新后为空订阅分组、URL 是否完整、有效期和返回格式；区分直连更新与通过代理更新。节点列表出现可识别的协议和服务器。
延迟正常，网页打不开活动服务器、系统代理、路由命中、DNS 与浏览器独立代理设置。目标请求出现在日志中，按预期走代理。
提示证书或握手错误设备时间、服务端证书、SNI、传输参数与配置来源。使用正确参数完成握手；保留证书验证。
TUN 开启后内网失效企业 VPN、局域网路由、DNS 和私有网段排除规则；先暂停 TUN 验证。本地服务恢复，并按需要明确配置直连规则。
退出后断网系统代理是否仍指向本机端口，TUN 与 DNS 是否恢复。关闭残留设置后可正常直连。

更多场景见常见问题；尚未确定客户端时，先看客户端对比，其他设备的操作入口见教程中心。
