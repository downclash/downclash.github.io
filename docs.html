先找对核心的文档

v2rayN、v2rayNG 与 V2rayU 是配置管理和操作界面；连接协议、路由和 DNS 处理由实际启动的核心完成。先从日志或关于页面记录核心名称与版本，再选择 V2Fly、Xray 或 sing-box 对应文档。客户端能导入节点不等于当前核心支持其中每个字段。

图形客户端可能在启动时生成配置。通过客户端设置修改时，应检查实际生效值；维护自定义完整配置时，则需确认哪些部分仍由客户端管理。

先识别手里的配置是什么

类型通常包含使用方式与边界
订阅 URL远程配置获取地址，常附账户令牌添加到客户端订阅管理并更新；返回内容可能是分享链接列表、YAML 或其他格式，需先确认客户端支持
单节点分享链接节点协议、地址、端口与认证等参数通过对应链接 / 剪贴板 / 二维码入口导入；通常不包含一整套 DNS 与路由策略
V2Fly / Xray JSONinbounds、outbounds、routing 等核心配置交给对应核心或支持该格式的自定义配置入口；同名字段也需核对版本，不能假定互通
sing-box JSONinbounds、outbounds、route、dns 等使用 sing-box 对应版本的配置结构；与 Xray JSON 不是同一种格式
Clash / Mihomo YAML常见节点、策略组与规则定义需要兼容的导入实现；即使节点可导入，也不能默认保留全部策略组、规则与 DNS 语义

客户端提示“格式错误”时，先检查返回的是否是登录页面或错误 HTML，再检查配置类型。不要把 .yaml 重命名成 .json；不要因支持某一协议就推断支持所有订阅格式。涉及账号令牌的订阅应直接在受信任客户端中处理。

操作教程：配置格式详解 · 订阅导入步骤

一条节点连接，至少分三层看

层次例子需要核对
代理协议VMess、VLESS、Trojan、Shadowsocks地址、端口、UUID / 密码，以及协议特有字段
传输RAW / TCP、WebSocket、gRPC 等与服务端相符的类型、路径、Host 或 serviceName；不同核心与版本命名可能变化
传输安全TLS、REALITY服务器名称、证书验证或公钥 / short ID 等对应参数；REALITY 不是独立代理协议

“VLESS + WebSocket + TLS”描述的是组合；只选择 VLESS 而缺少正确传输或 TLS 参数，仍无法建立预期连接。flow、公钥、路径和 SNI 不能根据节点名字猜测，应由配置提供方确认。

遇到证书错误先核对设备时间、服务器名称和服务端证书。不要通过关闭证书验证来把错误隐藏起来。查看协议、传输与核心兼容详解。

路由：把匹配条件映射到明确的出站

路由会把域名、IP、端口等条件映射到出站。规则顺序与未匹配连接的默认行为会影响最终结果；客户端中的“全局”“绕过局域网”等预设还可能重新生成规则。排查时应查看实际生效模式和日志。

下面是 Xray 的 routing 字段结构片段，只演示把指定域名交给一个出站。它没有定义对应出站、入站或认证信息，不能独立运行；不要直接替换客户端生成的完整配置。

{
  "routing": {
    "domainStrategy": "AsIs",
    "rules": [
      {
        "type": "field",
        "domain": ["domain:example.com"],
        "outboundTag": "proxy-example"
      }
    ]
  }
}

example.com 是占位域名；proxy-example 必须对应完整配置中的出站 tag。此片段使用 Xray 的 domain 字段，不能原样作为 sing-box 的 route.rules。使用 GeoIP、Geosite 或规则集时，还需保证文件 / 资源存在并与核心格式匹配。

验证方法：请求一条目标域名，确认日志中的目标与出站标签；再请求一条不应匹配的域名，检查默认行为。涉及局域网服务时同时检查私有 IP 的路由与 TUN 排除设置。

DNS：先弄清是谁在解析哪个域名

一次连接可能同时涉及节点服务器域名、目标站点域名，以及浏览器或应用自己的 DNS。系统 DNS、核心内置 DNS 和应用的安全 DNS 可能走不同路径；更改其中一项不代表其他路径也会随之改变。

观察到的情况优先核对验证结果
节点域名解析失败节点地址是否正确、当前网络解析是否可达核心日志能完成节点服务器的地址解析
核心能启动，但目标域名失败核心 DNS 的查询出口、上游可达性、目标分流规则解析请求与连接出站按预期完成
浏览器与其他应用表现不同浏览器安全 DNS、应用独立代理、系统 / TUN 接入确认是哪条解析与代理路径造成差异
开启 TUN 后内网名称失效本地 / 企业 DNS、私有域名规则、路由排除内网名称仍由合适的本地解析路径处理

不要把“统一改为某个公共 DNS”当成所有问题的修复方式。调整前记录原值，每次只改一项；企业网络与内网域名通常还需要其指定的解析路径。sing-box 的 DNS 结构随版本有迁移变化，先对照安装版本再复制配置。

系统代理、VPN 与 TUN 接入有什么区别？

入口适合的检查起点常见限制
系统代理先用读取系统代理的浏览器验证部分终端、游戏或应用不读取系统设置，需独立设置代理
应用指定代理核对 HTTP / SOCKS 类型、127.0.0.1 与真实端口只影响该应用；错误端口与协议会导致连接失败
Android VPN 接口确认授予 VPN 权限并处于运行状态其他 VPN、应用排除与后台限制可能影响流量接入
桌面 TUN确认客户端支持、权限 / 服务就绪、虚拟网卡与路由建立DNS、路由、IPv6 与其他 VPN 可能相互影响；流量范围由配置决定

先用已知可用节点验证系统代理或应用指定代理，再增加 TUN，有助于区分“节点本身不可用”和“流量没有接入”。遇到内网访问问题，先检查实际私有网段与排除规则，不要直接把内网流量交给远端节点。

在 sing-box 的 TUN 文档中，auto_route 用于配置自动路由，route_exclude_address 涉及排除地址；具体平台支持与其他路由选项应以当前版本文档为准。在 GUI 中优先通过受支持的设置入口管理，避免手工文件被下次启动覆盖。

操作教程：TUN 操作与恢复 · 系统代理 · 局域网共享

用日志确认问题发生在哪一层

  1. 核心启动前：看缺少文件、未知字段、端口占用或权限错误；记录客户端版本和核心版本。
  2. 请求进入时：确认目标域名 / IP 与路由匹配；没有请求时优先查入口。
  3. 连接建立时：区分 DNS 错误、连接超时、认证失败与 TLS 错误，各自核对相应参数。
  4. 目标响应时：代理通道可用并不保证目标服务接受该出口、账户地区或请求内容。

反馈时提供设备系统、客户端 / 核心版本、错误时间与脱敏后的最短错误片段。隐藏完整订阅 URL、UUID、密码、密钥与个人目标信息。继续阅读连接与速度排查。
