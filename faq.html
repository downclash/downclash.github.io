安装与客户端选择

V2Ray、v2rayN、v2rayNG 和 V2rayU 是同一个软件吗？

V2Ray / V2Fly、Xray、sing-box 是负责连接、协议和路由的内核。v2rayN 是 Windows、macOS、Linux 的图形客户端；v2rayNG 面向 Android；V2rayU 是独立的 macOS 客户端。客户端名称相似，不代表内核、导入格式或操作入口完全相同。先用客户端选择表确认平台，再看对应教程。

x64、ARM64、Universal 和 Source code 应该下载哪个？

先在系统的设备信息中确认 CPU 架构。Windows / Linux 的 Intel、AMD 电脑通常选 x64 / amd64，ARM 设备选 ARM64；Mac 的“关于本机”显示 Apple 芯片时选 arm64，Intel 机型选 x64。Android 不确定架构时可查看是否提供 Universal APK。Source code 是源码压缩包，不能当作已编译程序直接安装。具体系统要求以当前发布说明为准，见下载中心。

下载后打不开，或提示缺少运行时怎么办？

先确认下载包与系统、架构一致，并完整解压 ZIP 后启动，避免只从压缩包内运行主程序。然后根据该版本发布说明核对是否需要运行时、最低系统版本或额外组件；不能照搬其他版本的安装要求。若系统提示安全拦截，先核对来源与文件校验信息，再按操作系统和项目说明处理。不要通过关闭全局安全防护解决安装问题。

Android 安装失败，或升级提示签名不一致怎么办？

检查下载是否完整、架构及最低系统版本是否匹配，并只为本次安装使用的浏览器或文件管理器授予未知来源安装权限。签名冲突可能来自不同分发渠道，不能通过反复覆盖安装解决。先导出配置并确认备份可用，再决定是否统一到同一可信渠道；卸载会删除应用数据，操作前保留订阅地址和自建节点参数。见Android 安装与连接教程。

订阅与配置导入

订阅链接和 vmess://、vless:// 分享链接有什么区别？

订阅通常是可更新的 HTTP(S) 地址，用于获取一组配置；vmess://、vless:// 等通常描述单个节点。前者应在订阅管理中添加并更新，后者使用剪贴板、二维码或链接导入入口。导入后检查节点名称、协议和服务器是否出现。把订阅地址当作单节点链接导入，常会得到空列表或解析错误。详见配置格式说明。

更新订阅后没有节点，应该先查什么？

先看更新日志：超时通常指向网络或域名解析；401 / 403 需要检查授权、订阅地址与账户状态；解析失败需核对返回格式。确认复制的是完整订阅地址，而不是官网登录页、购买页或过期地址。再向配置提供方确认适合该客户端的格式。预期结果是更新成功并加载节点；不要只以“订阅已保存”作为导入成功的依据。

Clash YAML 能直接导入所有 v2ray 客户端吗？

不能。Clash / Mihomo YAML、节点分享链接和内核 JSON 属于不同配置形式，各客户端、版本支持的导入范围也不同。部分新版本提供格式兼容，但不能据此推断旧版或其他客户端同样支持。优先获取提供方明确标注适用客户端的订阅，导入后逐项确认节点协议、传输与路由结果。迁移前查看两类配置工作流对比。

订阅或二维码可以发给别人帮忙检查吗？

订阅地址、UUID、密码和节点二维码都可能包含连接凭据。求助时只提供已脱敏的错误类型、系统版本、客户端及内核版本，并遮盖链接中的 token 和认证参数。如果已经公开泄露，应在配置提供方处重置订阅或凭据，再更新客户端。不要把真实订阅粘贴到陌生的在线转换或检测网站。

连接与访问验证

节点有延迟数值，为什么浏览器仍然打不开网页？

延迟测试只覆盖测试所用的连接过程，不能证明目标网站可达。先确认该节点已设为活动节点、内核正在运行；桌面端核对系统代理是否开启及本地端口是否与实际监听一致，Android 核对 VPN 是否已连接。再访问目标网站并查看同时段日志。若浏览器仍无请求日志，优先检查流量是否进入客户端，见连接验证步骤。

只有终端或某个应用没有走代理，应该怎么处理？

系统代理只影响遵守该设置的应用。有独立代理选项的程序，可以填入客户端实际监听的 HTTP 或 SOCKS 地址和端口；终端也需按工具的代理选项配置。需要接管更多应用时，再比较当前客户端提供的 TUN 功能。一次只调整一种接管方式，并通过目标程序的实际请求日志验证。不要把浏览器成功直接当作所有应用成功。

切换到移动网络就失败，但 Wi-Fi 正常，怎么定位？

保留同一节点与配置，对比两种网络下的错误日志和失败时间。域名解析失败先检查 DNS 路径，连接超时再检查目标地址、端口及网络可达性；TLS 错误则核对证书相关字段和系统时间。一次更换一个条件，例如改用另一条已知可用节点，记录结果。两种网络行为不同并不足以确定是客户端故障，见连接诊断顺序。

更新客户端或内核后出现 TLS、证书或 unknown field 错误怎么办？

先记录升级前后客户端、内核版本，并阅读对应发布说明。TLS 或证书错误需要核对系统时间、服务器证书、SNI 和配置参数；字段错误需要对照该内核版本的文档，检查旧配置是否仍兼容。保留原始配置，使用提供方支持的新格式重新导入并复测。不要通过跳过证书验证来掩盖配置或证书问题，见协议与传输字段说明。

DNS、路由与 TUN

系统代理和 TUN 有什么区别，是否要同时开启？

系统代理通知应用使用本地代理端口；TUN 通过虚拟网络接口和路由接管更多流量，通常还涉及权限、DNS 及与其他 VPN 的共存。首次配置先确认一种方式可以正常工作，再按应用需求选择。两者是否配合使用取决于客户端实现与当前配置，不能用“同时全开”代替排查。详见TUN 配置检查项。

启用 TUN 后内网、打印机或公司服务无法访问怎么办？

先关闭 TUN 做一次对照，确认问题是否随接管方式变化；再检查内网域名解析、私网地址和公司 VPN 的路由是否冲突。根据实际网段设置排除路由或直连规则，并再次访问同一服务验证。只补一条直连规则未必能解决 DNS 或路由已被另一 VPN 接管的问题。处理工作网络时保留原设置，必要时按公司的网络配置要求恢复。

DNS 报错时可以直接换一个“最快 DNS”吗？

先分清是节点服务器域名无法解析，还是目标网站解析失败，再检查当前使用的是系统 DNS、内核 DNS 或 TUN 的 DNS 接管。更换解析器之前，确认新解析器可通过对应直连或代理路径访问，避免形成依赖代理才能解析代理服务器的循环。保留原配置，一次只改一个设置，用同一域名和实际网页请求复测。DNS 可解析不代表后续连接一定成功。

退出、恢复与反馈

退出客户端后，电脑断网了怎么办？

先检查操作系统的手动代理或自动配置地址，确认是否仍指向已经停止监听的本机端口。重新打开客户端，执行清除系统代理、停止 TUN，再正常退出；Android 则断开应用 VPN。若曾手动修改系统 DNS 或代理，应恢复自己记录的原值。最后确认普通网站能在直连状态打开，再重新配置。参见v2rayN 退出与恢复。

更换设备或升级前，需要备份哪些内容？

至少保存客户端支持的配置导出、订阅来源、手动节点及自定义规则，并记录系统代理、DNS、TUN 等关键设置。优先使用该客户端当前版本的备份功能，不能假设不同软件的数据目录可以互相覆盖。恢复后先验证一个节点，再逐项恢复分流和接管方式。备份本身也含敏感信息，应保存在可信位置；Mac 用户可参照V2rayU 配置教程。

在哪里查看官方文档，反馈问题时需要提供什么？

优先查对应客户端的项目 Wiki、发布说明和 Issues。报告应包含系统、CPU 架构、客户端版本、内核版本、接管方式、可复现步骤、失败时间及已脱敏日志，并说明其他网络或节点的对照结果。不要提交完整订阅、UUID 或密码。本站是独立的软件资料站，不是客户端开发团队；源码问题需前往对应项目的官方反馈入口。
